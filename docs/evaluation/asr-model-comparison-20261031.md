# 新しい音声認識モデルの比較（2026-10-31）

Whisper small（現行）、Haas-ja-v1.0、NVIDIA Nemotron 3.5 Transcribe を、同じ架空の会議音声で比べました。
評価したのは文字起こしの精度と、それを同じ議事録処理（Qwen3-4B）に渡したときの議事録の品質です。
本番アプリの設定や既定値は変えていません。手順とスクリプトは [tests/asr/eval/README.md](../../tests/asr/eval/README.md) にまとめてあります。

> **追記（2026-11-01）:** この時点で実行できなかった Haas-ja-v1.0 は、speech.cpp の Windows Vulkan 版で検証しました（[asr-haas-ja-20261101.md](asr-haas-ja-20261101.md)）。
> また、23.7分の会議では Nemotron の出力が約12.5分で途切れ、後半が欠落することが分かりました。下の「6.4分では欠落なし」は、長い会議には当てはまりません。

**結論:** Nemotron に替えると、議事録の重要事項は Whisper の 75〜76/129 から 115〜116/129 に上がりました。正解の台本を渡した場合（119/129）に近い値です。
ただし、この PC では CPU で実時間とほぼ同じ時間がかかり、RAM を約36GB使います。そのため、すぐに既定を置き換えられる状態ではありません。

### 分かったこと

**Nemotron の精度**
- 正規化後の CER は、Whisper（現行）の 1/2〜1/4 でした。数値は全会議で全問正解し、発言の欠落もほぼありません。原音にない文の挿入（幻覚）は、どちらのモデルにもありませんでした。

**架空の固有名詞の扱い**
- Nemotron は「佐倉→さくら／桜」「青嶺→精霊／聖霊」「冬期→冬季」と書き、指示文で用語を渡してもほとんど直りませんでした（h01 の用語 10/20 のまま）。
- Whisper のヒントは、「青嶺学院」など綴りが特殊な語には効きます（用語 4/20 → 10/20）。

**現行 Whisper の不具合（ヒントで文がまとめて抜ける）**
- h01 では、ヒントありのほうが CER が悪く（17.7% 対 10.1%）、発言が抜けました。
- アプリの区切り（68.1〜89.8秒）をそのまま再現すると、ヒントありでは Whisper が最初の1文で出力を打ち切り、続く約17秒（4発言、提案を含む）を出しませんでした。ヒントなしでは最後まで出力されます。
- ヒントの反響を捨てる処理が原因ではありません（`AsrHintDiag` で確認）。
- 本番の既定設定のまま黙って文が欠ける不具合です。今回は比較が目的なので、修正していません。

**Nemotron の句読点が消えることがある**
- h02 の雑音なし音声（指示なし・用語指定とも）だけ、出力に句点がまったくありませんでした（6.4分で1文）。雑音ありや話者分離の指示では付きました。
- 文の区切りがないと、議事録処理の「1文」が巨大になり、Next Action が減ります（1/6 対 4〜5/6）。

**Nemotron の単語の時刻が出ないことがある**
- d89 と h01 のほとんどの実行で、単語ごとの時刻が空でした（h02 と s01 では出力された）。エラーは出ません。

**Nemotron の話者の区別**
- 話者分離の指示: h01 で38発言中27発言が正解（4人を2人と推定）。h02 では話者タグが出ませんでした。
- CLI の `--diarize`: h02 で77発言中56発言が正解（3人と推定）。h01 では出ませんでした。
- 実用には不安定です。Whisper は話者分離に対応していません。

**速度とメモリ**
- Nemotron（CPU）は実時間とほぼ同じ時間（読み込み込み）がかかり、RAM を約36GB使います。
- Whisper（GPU）は実時間の約3%で、RAM 0.4GB、VRAM 0.8GB です。

  - 「〜してください」型の依頼が Next Action にならない（10/30）
  - 撤回された決定が【決定】のまま残る
  - 「要確認」が多い
- **Nemotron は句読点が消えると議事録が崩れます。** 雑音なし・指示なしの条件では、決定 6/30、Next Action 3/30 に下がりました。

## 6. 採点処理の不具合（修正済み）

- 議事録の採点が「三十万円」と「30万円」を同じと判定できていませんでした。アプリの `Numerals.Arabic` が「3万」の「万」を0として読むためです。
  - 採点側で、算用数字と万・千の混在表記を先に整数へ直すよう修正しました。
  - 「五十六点四」と「56.4」も同じと判定するようにしました。
- この修正で、前回報告した既存ベンチマークの数値が上がります（保存済みの下書きを数え直した結果）。

  | データ | 修正前の採点 | 修正後の採点 |
  |---|---|---|
  | 既存6件 v0.10.0（重要事項） | 109/123 | 115/123 |
  | 既存6件 A+B 修正後 | 114/123 | 120/123 |
  | 新しい5件 | 102/108 | 105/108 |

  修正前後の優劣は変わりません。
- アプリの `Numerals.Arabic` 自体の不具合（数値の照合で「80万円」と「八十万円」が一致しない）は、議事録処理の別の不具合として残っています（未修正）。
- 文字起こしの採点（`score_asr.py`）でも、「二十八人」が「208人」になる誤り、長音「ー」の削除、「3万2千」の混在表記の誤りを見つけて直しました。正規化の自己テストで確認しています。
