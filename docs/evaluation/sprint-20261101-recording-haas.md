# 録音とAI処理の分離・Haas-ja の統合・社用PC向け検証（2026-11-01）

本番の既定は変えていません（文字起こしは Whisper のまま。Haas-ja は設定で選ぶ試験的な機能）。
push・Release・アップロードはしていません。データはすべて架空です。

## 1. 録音とAI処理の分離

### 原因
- 録音・音声処理・文字起こしが、1つの状態（`VoiceState`：待機／録音中／処理中／文字起こし中）で管理されていた。
- 文字起こし中は録音ボタンが「文字起こしを中止」に変わり、処理中は押せなかった。そのため、前の録音の文字起こしが終わるまで次の録音を始められなかった。
- 文字起こしの結果は、単一の `_recordingNoteId` の宛先に入っていた。
- 議事録は録音中・文字起こし中には作成を拒否していた。

### 設計
| 部分 | 内容 |
|---|---|
| 録音 | `AudioRecorder.StopCaptureAsync` でファイルを閉じたら、すぐに次の録音を始められる。WAV の作成（`PrepareAsync`）は後の処理で行う |
| AIジョブ（`AiJobQueue`、Core） | 文字起こしと議事録を、録音とは別の永続キューで1件ずつ処理する（Pending／Running／Completed／Failed／Interrupted）。各ジョブは録音セッションとノートIDを持つ。`ai-jobs.json` には ID・パス・状態だけを保存し、本文は入れない |
| 再起動・異常終了 | 実行中だったジョブは Interrupted になり、次の起動時に再開する。3回続けて中断したら Failed にする（起動のたびに落ちる事故を防ぐ） |
| メモリ | 物理メモリの空きを確認し、足りなければ待機する（「メモリの空き待ち」と表示）。モデルは同時に1つまで（Whisper は議事録の前に解放する） |
| データ保全 | 文字起こしをノートに保存したことを確かめてから、音声を削除する（先に `delivered` と記録するので、再起動しても二重に追加しない）。終了確認のダイアログが出ている間は、ノートへの追加を保留する |
| 中止 | 推論エンジンの中止トークンだけを使う。強制終了はしない（Haas-ja は別プロセスなので、そのプロセスだけを終了する） |

### テスト（E2E の jobs スイート、29項目）
- 面談Aの文字起こし中に、面談Bの録音を開始できた（193ms）。
- 3件を連続で録音し、それぞれのノートに自分の文字起こしだけが入った。
- 終了時に処理中だったジョブは、再起動後に再開した。
- プロセスを強制終了しても、録音が残り、再開後にノートへ1回だけ追加された。
- 文字起こし待ちの間に依頼した議事録は、文字起こしの後に作成された。

### 処理中に見つけて直した不具合
| 不具合 | 対処 |
|---|---|
| 終了ダイアログの表示中にジョブが終わると、文字起こしが保存前に消え、音声も削除された | 上記の保留と、保存の確認を追加 |
| Vulkan のモデル読み込み中に、エディタのキーボードフォーカスが外れた（従来も、最初の文字起こしの間ずっと入力できなかった） | 読み込み直後にフォーカスを戻すようにした（空白は約0.4秒）。Haas-ja は別プロセスなので発生しない |
| 議事録の進捗通知が別スレッドから UI を操作し、アプリが落ちた | UI スレッドに渡すようにした。バックグラウンドの例外も crash.log に記録する |

## 2. Haas-ja の統合

- `SpeechCppTranscriptionService`：speech.cpp v0.10.0 を別プロセスで実行する。終了コード・標準出力の JSON・標準エラーを確認し、全区間の結果がそろわなければ失敗とする。タイムアウトと中止にも対応する。
- `SpeechChunker`：Silero VAD（無音150ms）→ 0.5秒未満の間を結合 → 0.9秒未満の区間（「はい」など）は単独で認識 → 20秒を超える区間は最も静かな点で分割 → 間で終わる区間に「。」を補う。
  - 値は開発用データ（d02、s01、d89）だけで決めた。
- カスタム語彙：辞書で「認識のヒント」にした語を使う（読みがかなの場合は「表記=よみ」）。辞書の形式は変えていない。
- 設定に「音声認識のエンジン」を追加した。次の録音から反映され、既定は Whisper のまま。

## 4. そのほかの未解決課題
| 課題 | 結果 |
|---|---|
| Whisper のヒントによる欠落 | 修正した。区間の末尾に3秒以上の音声が残ったら、ヒントなしで再認識する。h01 の CER は 17.7%→9.7%、欠落は 4→2 |
| 数値の正規化（アプリ側） | 「30万円」が「300円」と一致する不具合を修正した。議事録の結果は変化なし |
